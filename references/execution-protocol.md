# 执行层协议

## 一、渐进增强架构

三级降级体系，确保任何环境下可用：

| 级别 | 模式 | 条件 | 能力 |
|------|------|------|------|
| L1 | 脚本增强 | Node.js ≥18 + Python ≥3.8 均可用 | 全部脚本可执行，精确计算 |
| L2 | CLI基础 | 仅Python或仅Node.js可用 | 可用部分脚本，其余降级为LLM推理 |
| L3 | 纯知识 | 无脚本环境 | 仅SKILL.md+references知识，LLM直接推理 |

### 降级策略

1. **脚本调用失败** → 优雅降级：输出错误信息 + 切换为LLM推理 + 记录降级事件
2. **连续失败**（同一脚本3次） → 标记脚本不可用，本次会话不再调用
3. **环境检测** → 首次调用脚本前检测运行时，缺失则直接进入L3

## 二、环境前置检查

调用任何脚本前，必须验证：

```bash
# Python 脚本
python --version 2>&1 || python3 --version 2>&1

# Node.js 脚本
node --version 2>&1
```

- Python ≥3.8 → 可用 financial_calculator.py
- Node.js ≥18 → 可用 state.mjs / deploy.mjs / knowledge-filter.mjs
- 两者均不可用 → 进入L3纯知识模式

## 三、脚本清单

| 脚本 | 类型 | 用途 | 降级行为 |
|------|------|------|----------|
| financial_calculator.py | Python | 财务模型计算（一次性/订阅/对比） | 降级为LLM估算 |
| state.mjs | Node.js | 项目状态管理 | 降级为LLM记忆+手动记录 |
| deploy.mjs | Node.js | 多AI Host部署入口生成 | 降级为手动复制exports/ |
| knowledge-filter.mjs | Node.js | 知识库精准加载过滤 | 降级为全量加载（可能上下文溢出） |

## 四、知识加载策略

- 每次交互最多加载5个reference文件（通过knowledge-filter.mjs过滤）
- 入口驱动加载：根据用户请求的入口点（全链路/国家定向/行业定向/单层/每日/新手）精准匹配
- 层级驱动加载：全链路模式下按当前层级加载对应reference
- 溢出保护：超过5个文件时按优先级截断，优先加载与当前入口/层级最相关的

## 五、失败处理规则

1. 脚本输出非JSON → 解析失败 → 降级为LLM推理 + 记录错误
2. 脚本退出码≠0 → 读取stderr → 向用户展示错误 + 提供替代方案
3. 脚本超时（>30秒） → 终止 → 降级为LLM推理
4. 文件不存在 → 跳过 + 记录 + 继续执行其余流程
